# Brick Earthquakes Tracker

Brick is a native Android application for exploring earthquakes reported by the [USGS Earthquake API](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php). It presents the same recent activity as a list and on a map, provides an event detail view, supports manual refresh, and keeps previously loaded earthquake data available when a network request fails.

## Features

- Recent worldwide earthquakes from the USGS all-day GeoJSON feed.
- A list with magnitude, location, local event time, visual magnitude ranges, tsunami highlighting, and local sorting by newest or strongest event.
- Pull-to-refresh with clear loading, empty, cached-data, and error states.
- A full-screen map with marker clustering for dense areas.
- Optional current-location context. If permission is granted, the map displays the standard location indicator and recenter button; the earthquake map remains usable if permission is denied or location is unavailable.
- Event details with magnitude, location, time, depth, coordinates, and an embedded map.
- Offline fallback through the HTTP cache after previously loading data.

## Requirements

- Android Studio with its bundled JDK selected as the Gradle JDK.
- Android SDK 37.1 installed.
- A device or emulator running Android 8.0 (API 26) or newer.
- A Google Maps API key supplied by Mauricio for the evaluation.

## Setup and run

1. Clone the repository and open its root directory in Android Studio.
2. Request the Google Maps API key from Mauricio. A reviewer does not need to create a separate Google Cloud project for this evaluation.
3. Keep the `sdk.dir` generated by Android Studio in the root `local.properties` file and add the supplied key without quotes:

   ```properties
   sdk.dir=/path/to/your/Android/sdk
   MAPS_API_KEY=KEY_PROVIDED_BY_MAURICIO
   ```

4. Sync the project with Gradle.
5. Select the `app` run configuration and run it on a device or emulator.

`local.properties` is excluded from Git and the API key must not be committed. Without a configured key, the earthquake list and details still work, while map surfaces display an unavailable message.

The project can also be built from the command line:

```bash
./gradlew :app:assembleDebug
```

The debug APK is generated under `app/build/outputs/apk/debug/`.

If command-line Gradle reports an invalid `JAVA_HOME`, configure it to use Android Studio's bundled JDK. Android Studio itself can be configured under **Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JDK**.

## Architecture

The app uses a small, single-module structure with a unidirectional UI state flow:

```text
Compose screens
      ↓ events                         ↑ StateFlow<EarthquakeListUiState>
EarthquakeListViewModel
      ↓
EarthquakeRepository interface
      ↓
DefaultEarthquakeRepository
      ↓
Retrofit API + OkHttp HTTP cache
```

- `data/earthquake/network` contains the Retrofit API and serializable USGS response models.
- `data/earthquake` maps network models into the smaller domain model used by the UI. The repository interface allows the ViewModel to be tested with a fake implementation.
- `feature/earthquakelist`, `feature/earthquakemap`, and `feature/earthquakedetail` contain the Compose UI for each feature.
- `EarthquakeListViewModel` owns the shared feed and exposes one immutable `StateFlow` snapshot containing data and transient UI conditions.
- `EarthquakeNavHost` defines type-safe list, map, and detail destinations. Routes carry only the earthquake ID; the map and detail screens reuse the feed already held by the shared ViewModel instead of making another USGS request.
- Hilt provides the repository, Retrofit, OkHttp, JSON parser, cache, and interceptor.

Primary libraries are Jetpack Compose and Material 3, Navigation Compose, Google Maps Compose, Maps Compose Utils, Hilt, Retrofit, OkHttp, Kotlin Serialization, and Kotlin Coroutines.

## Important technical decisions

### Refresh and offline behavior

The app uses a 10 MB OkHttp disk cache rather than a database. Initial loading and pull-to-refresh request fresh data. If the network call throws an `IOException`, an interceptor retries from cache and accepts a cached response up to seven days old. The UI tells the user when saved data is being shown. If no cached response exists, the normal error state remains available.

This keeps the solution proportional to the exercise while preserving previously viewed data. The cache is recoverable application data and Android may clear it, so it is not treated as permanent storage.

### Maps and location

The list and map use the same USGS feed. The map starts over the contiguous United States but continues to include worldwide events. Nearby markers are grouped by the clustering utility according to zoom level; selecting a cluster zooms in, and selecting an individual event opens its detail screen.

Foreground location permission is requested only when the full-screen map opens. Granting approximate or precise location enables Google Maps' standard current-location indicator. Denying permission does not block earthquake exploration.

Google Maps tiles are managed separately by the Maps SDK and are not part of the USGS HTTP cache.

### Information hierarchy

Magnitude remains visible as a number and is reinforced by four presentation colors: green below 2.5, yellow from 2.5 through 4.4, orange from 4.5 through 5.9, and red from 6.0 upward. These are UI categories rather than an official damage scale. Events flagged by USGS for possible tsunami activity use a red card background independently of the magnitude color.

The list can be sorted by `Latest` or `Strongest`, with `Latest` selected by default. Sorting is performed locally on the already loaded feed, so changing the option does not make another network request or modify the data shared with the map and detail screens. The selected option lives in the ViewModel state and survives refreshes and navigation.

## Assumptions and tradeoffs

- “Recent” means the USGS `all_day.geojson` feed; the app does not combine multiple feed windows.
- Details reuse the summary feed because it already contains the information shown by the app. The USGS detail URL is retained in the domain model for a possible future expansion.
- The current location provides geographic context on the map but is not used to calculate distance, reorder results, or filter earthquakes.
- A disk HTTP cache was chosen instead of Room to fit the 4–6 hour timebox and avoid duplicating the server response in another persistence layer.
- The map opens over the United States because that is the expected primary viewing area, while the underlying feed and markers remain worldwide.
- Navigation passes stable event IDs rather than serializing complete earthquake objects.

## Testing

Run the unit test suite with:

```bash
./gradlew :app:testDebugUnitTest
```

Or build and test together:

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Automated tests cover:

- Mapping a representative USGS response into the domain model.
- Returning a stale cached response when a network request fails.
- ViewModel initial loading and failed-refresh behavior, including preserving existing data.
- Preserving the selected sort option across a refresh.
- Latest/strongest ordering, magnitude-band boundaries, and parsing the region from USGS place descriptions.

The current suite emphasizes deterministic data and state behavior. Map rendering, runtime permission dialogs, navigation gestures, and visual presentation are best checked manually because they depend on Android and Google Play services. Before submission, useful manual checks include accepting and denying location permission, navigating list → map → detail → back, selecting clusters at different zoom levels, refreshing online, and reopening previously viewed data without connectivity.

## Known limitations and next steps

- The supplied Google Maps key is required for map rendering and should be requested from Mauricio rather than committed.
- The HTTP cache can be evicted by Android and only accepts stale earthquake responses for seven days; durable offline storage would require a database.
- Location is displayed as map context, but distances from the user are not calculated.
- Events at identical coordinates may remain clustered at the highest zoom level. A cluster event picker could make those events individually selectable.
- The app does not yet provide filtering, background updates, or notifications.
- The automated suite does not currently include Compose UI or instrumentation tests.

With more time, the next priorities would be distance-aware presentation, persistent storage for reliable offline access, focused Compose navigation tests, and filtering by magnitude or distance.
